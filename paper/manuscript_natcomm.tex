\begin{abstract}
  \noindent
  Community detection in complex networks is often framed as modularity maximization. Over the past two decades, research on this problem has split into two largely separate communities: classical combinatorial heuristics that use only graph structure, and deep graph neural networks (GNNs) that include node attributes through continuous modularity relaxations. Because each community mostly tests against methods from its own paradigm, key trade-offs in solution quality, ground-truth recovery, scalability, and parameter sensitivity remain unclear. Here we benchmark 17 representative clustering algorithms from seven paradigms across attributed real-world networks, topology benchmarks with up to 3.3 billion edges, and synthetic graphs with controlled noise. Across three protocols covering default parameters, hardware acceleration, and hyperparameter tuning, we find that classical heuristics (\textsc{VieClus} and \textsc{Leiden}) lead in pure modularity and scalability without tuning. Conversely, GNNs recover semantic communities better when informative node attributes exist, but require careful tuning and large GPU memory.
\end{abstract}

\section{Introduction}\label{sec:introduction}
Networks are widely used to model complex systems across the natural sciences, social sciences, and engineering. In these graph models, vertices represent entities and edges capture interactions between them, such as in social networks, communication infrastructure, biological systems, and information networks. A common property of real-world graphs is \emph{community structure}, where vertices form groups with dense internal connections and sparser links to the rest of the network.

Finding these groups, known as \emph{graph clustering} or \emph{community detection}, is a core task in network analysis. Applications range from social analysis and fraud detection~\cite{Akoglu2015} to bioinformatics~\cite{Cai2011,Xu2002}, program optimization~\cite{Demme2012,McFarling89}, and epidemic modeling~\cite{Newman2003}. Beyond specific applications, community structure highlights the main organizational patterns of a network, such as cohesive subgraphs, boundary vertices, and interactions between groups. Because no single clustering method performs best on all network types~\cite{Peel2016}, new algorithms and comparative benchmarks remain active areas of research.

Most community detection methods treat clustering as an optimization problem over vertex partitions, assigning a quality score to each candidate solution. Many quality measures have been proposed, including coverage, performance~\cite{Gaertler2005}, inter-cluster conductance~\cite{kannan2004clusterings}, surprise~\cite{arnau2004iterative}, the Weighted Community Cluster (WCC) triangle objective~\cite{wcc2012,scd2014}, the information-theoretic Map Equation~\cite{infomap2008,infoflow2019,neuromap2024}, and modularity~\cite{girvan2002,Newman2006}. Among these objectives, \emph{modularity} is the most widely adopted in both theory and practice~\cite{dimacschallengegraphpartandcluster,Li2024}. It measures the fraction of edges inside communities compared to the expected fraction in a random graph with the same vertex degrees. This work therefore focuses on modularity-based methods, while also including widely used random-walk baselines.

Modularity-based algorithms fall into two broad categories. \emph{Classical} methods rely on discrete optimization heuristics driven only by graph topology and a well-defined objective function. In contrast, \emph{learning-based} methods build modularity into deep learning pipelines, most often through GNNs, and combine node attributes with graph structure through learned feature representations. While node features can provide valuable extra signal, learning-based pipelines also add training complexity, additional hyperparameters, and higher compute and memory requirements~\cite{neuromap2024,Wani2024}.

Despite active research in both communities, experimental comparisons between them remain fragmented. As illustrated in Figure~\ref{fig:comparisons}, papers introducing new algorithms rarely compare against methods from the other paradigm, with the 2008 \textsc{Louvain} algorithm~\cite{louvain2008} serving as one of the few shared baselines. Existing review articles also tend to focus either on classical heuristics~\cite{survey2023} or on deep learning methods~\cite{Liu2020,Jin2023,liang2024,Wani2024,Messias2025}. Li et al.~\cite{Li2024} compare classical and deep learning approaches, but restrict their experiments to Python packages, leaving out state-of-the-art C++ metaheuristics, streaming solvers, and recent GNN architectures. Even within the classical literature, perceptions can differ across subfields: for instance, Aref et al.~\cite{survey2023} note that simple heuristics often miss global modularity optima, whereas Ans{\'o}tegui et al.~\cite{maxsat2025} show that the memetic algorithm \textsc{VieClus}~\cite{vieclus2018} routinely finds provably optimal partitions on small and medium-sized networks.

Here we bridge this divide with a large-scale experimental benchmark of 17 representative community detection algorithms across seven optimization paradigms. We integrate all 17 solvers into an open-source benchmarking framework with standardized input/output formats, consistent timing and memory tracking, and an interactive companion website\footnote{\url{https://clusterbenchmark.github.io/}}. We evaluate all methods across three standardized protocols covering out-of-the-box defaults (Protocol~A), multi-core CPU and GPU hardware scaling (Protocol~S), and Bayesian hyperparameter tuning (Protocol~B). Using attributed real-world networks, topology-only benchmarks with up to 3.3 billion edges, and synthetic graphs with controlled structural and feature noise, our study clarifies when classical combinatorial heuristics suffice and when learning-based GNNs offer a genuine advantage.

Table~\ref{tab:comp} summarizes the 17 community detection algorithms integrated into our benchmark alongside surveyed methods whose source code is unavailable. The evaluated solvers span seven optimization families (described in detail in Section~\ref{sec:methods}): (1)~greedy agglomeration and multilevel local search (\textsc{CNM}, \textsc{Louvain}, \textsc{Leiden}), (2)~random-walk and flow baselines (\textsc{Walktrap}, \textsc{Infomap}), (3)~metaheuristics and memetic search (\textsc{COMBO}, \textsc{VieClus}), (4)~streaming algorithms (\textsc{Hollocou}, \textsc{CluStRE}), (5)~exact integer programming (\textsc{Bayan}), (6)~continuous and differentiable modularity optimization (\textsc{DMoN}, \textsc{GNNS}, \textsc{DGCluster}, \textsc{LIM}), and (7)~contrastive and mutual-information GNN architectures (\textsc{CommDGI}, \textsc{UCoDe}, \textsc{MAGI}).

We evaluate these methods across three datasets: the attributed \textsc{Ground-Truth} suite ($N=10$ real-world networks with node features and known community labels, up to $61.9$~million edges), the topology-only \textsc{DIMACS} suite ($N=32$ graphs from the 10th DIMACS challenge, up to $3.3$~billion edges), and synthetic attributed graphs generated with the Attributed Degree-Corrected Stochastic Block Model (ADC-SBM)~\cite{adcsbm2022}. Each run has a wall-clock time limit of 1~hour and a host memory limit of 120~GB (or 24~GiB VRAM on GPU). We measure topological clustering quality via modularity ($Q$) and ground-truth label agreement via Normalized Mutual Information (NMI) and edge-restricted Pairwise F1.

To compare algorithms across diverse graphs without distorting results through raw-score averages, we use the relative performance normalization of Dolan and Mor{\'e}~\cite{perf2002}. On each graph instance and quality metric, an algorithm's score is divided by the best score achieved by any method on that instance, giving a relative ratio $\tau \in [0, 1]$. Instead of plotting 17 overlapping cumulative step functions, we show a horizontal strip lane for each algorithm. Every solved instance appears as a marker at its ratio $\tau$ (with slight vertical jitter to separate overlapping points near $\tau = 1$), while unresolved instances due to time limits (TLE), memory limits (MLE), or runtime errors (ERR) appear as $\times$ markers in a separate \emph{Fail} band on the right. Algorithms whose markers cluster near $\tau = 1$ with few markers in the \emph{Fail} band achieve both high quality and broad scalability. Detailed per-instance results can be seen in Appendices~\ref{sec:memory}--\ref{sec:detailed-results} (Tables~\ref{tab:memory}--\ref{tab:mod_dimacs_large}).

\subsection{State-of-the-Art Comparisons (Protocol~A)}

Figures~\ref{fig:perf_quality} and~\ref{fig:perf_gt_recovery} show the out-of-the-box Protocol~A performance distributions for modularity maximization and ground-truth community recovery (full per-instance tables are provided in Appendix~\ref{sec:detailed-results}, Tables~\ref{tab:mod_gt}--\ref{tab:mod_dimacs_large}). Across both the attributed \textsc{Ground-Truth} graphs and the topology-only \textsc{DIMACS} suite (Figure~\ref{fig:perf_quality}), classical modularity heuristics clearly lead in pure modularity maximization. \textsc{VieClus} reaches the highest modularity on every instance it completes ($\tau = 1.0$ on 9/10 \textsc{Ground-Truth} graphs and 30/32 \textsc{DIMACS} graphs), matching prior findings~\cite{vieclus2018,maxsat2025}. It fails only on the largest instances (\texttt{ogbn-products}, \texttt{uk-2002}, and \texttt{uk-2007-05}) due to time, memory, or 32-bit edge-index limits. \textsc{Leiden} and \textsc{Louvain} follow closely behind. In particular, \textsc{Leiden} solves all 10 \textsc{Ground-Truth} instances with $\tau \ge 0.990$ and 31/32 \textsc{DIMACS} instances with $\tau \ge 0.953$. Among continuous and learning-based methods, only \textsc{DGCluster} ($\tau \ge 0.923$ on 8/10 \textsc{Ground-Truth} graphs) and the topology-driven \textsc{GNNS} ($\tau \ge 0.925$ on 10/10 \textsc{Ground-Truth} graphs and 28/32 \textsc{DIMACS} graphs) approach the modularity of classical heuristics. In contrast, contrastive and deep GNN models score much lower in raw modularity, especially on the featureless \textsc{DIMACS} graphs where they rely on synthetic degree-profile and random node features (\texttt{ldp+rni}).

When we evaluate ground-truth community recovery on the \textsc{Ground-Truth} dataset (Figure~\ref{fig:perf_gt_recovery} and Appendix~\ref{sec:detailed-results}, Tables~\ref{tab:nmi_gt} and~\ref{tab:f1_gt}), the picture changes substantially. Here, attribute-aware learning-based methods compete closely with, and often beat, pure modularity maximizers. In NMI (Figure~\ref{fig:perf_gt_recovery}, left), \textsc{MAGI} has the strongest overall profile (mean NMI of $0.533$ across 9/10 solved instances, with $\tau \ge 0.859$ on 80\% of instances), while \textsc{CommDGI}, \textsc{DGCluster}, and \textsc{UCoDe} each reach the highest NMI ($\tau = 1.0$) on several networks alongside \textsc{Leiden}. On edge-restricted Pairwise F1 (Figure~\ref{fig:perf_gt_recovery}, right), \textsc{MAGI}, \textsc{LIM}, \textsc{CommDGI}, \textsc{DGCluster}, \textsc{UCoDe}, and the flow-based \textsc{Infomap} all reach $\tau = 1.0$ on multiple instances. Notably, this advantage is not simply because fixed-$k$ neural models receive the true number of classes $|C|$. The cluster-free neural methods \textsc{DGCluster} and \textsc{LIM}, which infer $k$ automatically without knowing $|C|$, also outperform classical topology-only heuristics in NMI and Pairwise F1 on several citation and co-purchasing networks. Instead, the difference between Figure~\ref{fig:perf_quality} and Figure~\ref{fig:perf_gt_recovery} reflects a mismatch between topological modularity and semantic class labels. For example, on Citeseer, the ground-truth class partition has a modularity of only $0.54$, whereas classical and neural modularity maximizers find partitions with modularity up to $0.89$. Using node attributes helps GNNs group nodes by semantic topic even when citation links cross topic boundaries.

The streaming algorithms \textsc{Hollocou} and \textsc{CluStRE} trade solution quality for high scalability. Both solve all 10 \textsc{Ground-Truth} and all 32 \textsc{DIMACS} graphs, including \texttt{uk-2007-05} ($3.3$~billion edges), with \textsc{CluStRE} consistently outperforming \textsc{Hollocou} in both modularity and NMI/F1. At the opposite end of the spectrum, the exact branch-and-cut solver \textsc{Bayan} achieves the globally optimal modularity on six of the eight smallest \textsc{DIMACS} networks (\texttt{karate}, \texttt{chesapeake}, \texttt{dolphins}, \texttt{lesmis}, \texttt{polbooks}, and \texttt{football}, $\tau = 1.000$). On \texttt{adjnoun}, it reaches its one-hour solve budget with a feasible partition of $0.312$ (at a $23.9\%$ optimality gap, just below the $0.313$ optimum), and on \texttt{jazz} and larger graphs its $\mathcal{O}(n^3)$ triangular constraint formulation exceeds the one-hour time limit (\textsc{TLE}) or the 120~GB memory limit (\textsc{MLE}). Across the eight smallest \textsc{DIMACS} instances with known globally optimal modularity scores from exact ILP and MaxSAT solvers~\cite{bayan2024,maxsat2025}, \textsc{VieClus} finds the optimal modularity on all 8/8 instances, \textsc{GNNS} on 7/8, \textsc{Leiden} and \textsc{Bayan} on 6/8, \textsc{COMBO} on 5/8, \textsc{Louvain} on 4/8, and \textsc{DGCluster} and \textsc{Infomap} on 2/8.

Figure~\ref{fig:efficiency} (left) shows the wall-clock runtime distributions on the \textsc{Ground-Truth} dataset under Protocol~A ($p=1$) together with the average speedups gained from multi-core CPU ($p=32$) and GPU acceleration under Protocol~S. Across both the \textsc{Ground-Truth} and \textsc{DIMACS} suites, runtime per edge ($\mu\text{s}/m$) spans six orders of magnitude. Streaming algorithms (\textsc{Hollocou} at $0.04$--$0.05\,\mu\text{s}/m$ and \textsc{CluStRE} at $0.26$--$0.64\,\mu\text{s}/m$) are the fastest, finishing most graphs in milliseconds to seconds. Multilevel local-moving heuristics (\textsc{Leiden} at $0.78$--$0.85\,\mu\text{s}/m$ and \textsc{Louvain} at $1.74$--$2.12\,\mu\text{s}/m$) offer the best balance between speed and quality. They reach near-optimal modularity more than four orders of magnitude faster than the memetic solver \textsc{VieClus}, which uses its full 1-hour time budget to iteratively refine partitions. Among continuous and learning-based methods, the sparse matrix-free \textsc{GNNS} ($375\,\mu\text{s}/m$ on \textsc{Ground-Truth}) is ten times faster than deep neural architectures ($4\,300$--$26\,400\,\mu\text{s}/m$), which spend substantial time in multi-epoch gradient training.

Peak memory usage shows an equally clear divide between paradigms (see Appendix~\ref{sec:memory}, Table~\ref{tab:memory}). Streaming methods process edges in a single pass with minimal state and need only $1.1$~GB on \texttt{ogbn-products} ($61.9$~M edges), while \textsc{Leiden} and \textsc{Louvain} use $12.7$~GB. In contrast, GNNs store high-dimensional node embeddings and intermediate activations, requiring $14$--$47$~GB on medium and large graphs. Even worse, methods that build dense $O(n^2)$ modularity or similarity matrices in RAM, specifically \textsc{LIM}, \textsc{UCoDe}, \textsc{CommDGI}, and the Python setup phase of \textsc{Bayan}, try to allocate $214$~GiB on \texttt{ogbn-arxiv} ($n = 169\,343$) and over $41$~TiB on \texttt{ogbn-products}. These runs immediately fail with memory limit exceeded (\textsc{MLE}).

To measure how parallel hardware affects runtime and quality, \textbf{Protocol~S} runs the parallel and learning-based solvers with 32 CPU threads ($p = 32$, \texttt{device=cpu}) and with an NVIDIA RTX~4090 GPU ($p = 32$, \texttt{device=cuda}). Full per-instance runtimes are listed in Appendix~\ref{sec:par-seq} (Table~\ref{tab:par-seq}). Scaling from 1 to 32 CPU threads (Figure~\ref{fig:efficiency}, left, cyan triangles) gives geometric-mean speedups of $8.0\times$ for \textsc{UCoDe}, $7.6\times$ for \textsc{LIM}, $5.0\times$ for \textsc{DGCluster}, $3.7\times$ for \textsc{CommDGI}, and $3.4\times$ for \textsc{DMoN} across medium-sized networks. Moving training to the RTX~4090 GPU (orange diamonds) yields much larger speedups over single-threaded CPU runs, reaching geometric-mean speedups of $158\times$ for \textsc{LIM} (reducing \texttt{coauthor-physics} from $3\,615$~s to $40.5$~s), $100\times$ for \textsc{UCoDe}, $95\times$ for \textsc{CommDGI}, $37\times$ for \textsc{DGCluster}, $13\times$ for \textsc{GNNS}, and $12\times$ for \textsc{DMoN}.

Figure~\ref{fig:efficiency} (right) shows the modularity gain $\Delta Q = Q_{\text{accel}} - Q_{1\text{T}}$ on compute-bound instances across both datasets. For \textsc{VieClus}, running its evolutionary search across 32 MPI processes improves modularity slightly ($\Delta Q \in [0, +0.002]$) on medium graphs, but duplicating graph data across 32 MPI ranks exceeds the 120~GB RAM limit on the largest instances (\emph{MLE} band). For the neural methods, comparing completed training epochs on 1T~CPU (Appendix~\ref{sec:memory}, Table~\ref{tab:iterations}) and GPU (Appendix~\ref{sec:par-seq}, Table~\ref{tab:iterations_gpu}) explains why hardware acceleration improves quality. While small graphs finish all training epochs within an hour on 1T~CPU, larger networks such as \texttt{coauthor-physics} and \texttt{ogbn-arxiv} stop early at the 1-hour limit (for example, \textsc{DGCluster} completes $270/300$ epochs on \texttt{ogbn-arxiv}, and \textsc{LIM} completes $111/300$ on \texttt{coauthor-physics}). Finishing all training epochs on 32T~CPU or GPU rescues these runs and boosts modularity by $\Delta Q \in [+0.002, +0.22]$ (Figure~\ref{fig:efficiency}, right, epoch-rescue regime). At the same time, GPU execution introduces a tighter memory limit. Because the RTX~4090 has 24~GiB of VRAM compared to 120~GB of system RAM, full-graph GNNs run out of memory on smaller graphs on the GPU than on the CPU (orange diamonds in the \emph{MLE} band). For example, \textsc{CommDGI} needs $29.7$~GB on \texttt{coauthor-physics}, so it finishes on 32T~CPU but hits \textsc{MLE} on the GPU.

To test how strongly algorithm rankings depend on hyperparameter tuning versus default settings, \textbf{Protocol~B} runs 50 trials of Bayesian optimization with Optuna~\cite{optuna2019} on Cora, Citeseer, and Pubmed. The search maximizes unsupervised modularity $Q$ under the cluster-free regime ($k = \lceil\sqrt{n}\rceil$). The results show a clear difference in parameter sensitivity between classical and neural methods. Classical modularity heuristics (\textsc{Leiden}, \textsc{Louvain}, and \textsc{COMBO}) show almost no sensitivity ($\lvert\Delta Q\rvert \le 0.005$) because their default resolution parameter ($\gamma = 1.0$) already matches standard Newman--Girvan modularity. On Pubmed, tuning \textsc{COMBO}'s resolution and community cap also allows it to finish within the one-hour limit ($Q = 0.740$). For \textsc{Walktrap}, tuning the random-walk length $t \in [2, 12]$ gives small, steady gains ($+0.016$ to $+0.028$). For learning-based methods, comparing the default scores in Table~\ref{tab:protocol_b} ($k = \lceil\sqrt{n}\rceil$) with those in Table~\ref{tab:mod_gt} ($k = |C|$) highlights an important cluster-count effect. When fixed-$k$ neural models are restricted to the small number of ground-truth classes in Protocol~A ($|C| = 6$ on Citeseer and $|C| = 7$ on Cora), their maximum achievable modularity is capped (for example, $Q = 0.722$ for \textsc{MAGI}-SAGE and $0.698$ for \textsc{CommDGI} on Citeseer). Raising the cluster budget to $k = \lceil\sqrt{n}\rceil = 58$ in Table~\ref{tab:protocol_b} immediately increases their untuned modularity to $0.878$ and $0.813$. At the same time, finer partitions that maximize topological modularity split broad semantic classes into smaller sub-communities, which explains why tuning for $Q$ improves structural modularity rather than semantic NMI. Beyond the cluster budget $k$, neural models that balance multiple loss terms or depend on temperature scaling also benefit strongly from hyperparameter tuning. \textsc{GNNS} gains $+0.015$ to $+0.028$ by tuning its subspace rank and step count, while full-graph \textsc{MAGI} (GCN) improves by $+0.049$ to $+0.106$ and mini-batch \textsc{MAGI} (GraphSAGE) improves by $+0.049$ on Pubmed. Even after 50 trials of per-instance Bayesian optimization, however, no learning-based algorithm beats the untuned modularity of \textsc{VieClus} or \textsc{Leiden} on any of the three networks.

\section{Discussion}\label{sec:discussion}\label{sec:conclusion}
Our experimental benchmark of 17 modularity-based clustering algorithms connects two research communities that have largely developed in isolation: classical combinatorial optimization and deep graph representation learning. Evaluating both paradigms under identical time, memory, and hardware budgets reveals clear trade-offs between topological optimization quality, semantic community recovery, scalability, and ease of use.

When the goal is pure modularity maximization or fast partitioning of unattributed graphs, classical combinatorial methods remain the clear best choice. The memetic solver \textsc{VieClus} reaches the highest modularity on every instance it completes across both attributed and featureless datasets, and matches exact branch-and-cut (\textsc{Bayan}) and MaxSAT solutions on all small verification instances. For most practical applications, \textsc{Leiden} provides the best trade-off between quality and speed: it comes within $1\%$ of \textsc{VieClus} in modularity on the \textsc{Ground-Truth} suite while running more than four orders of magnitude faster and requiring no parameter tuning. At web scale, where even multilevel heuristics exceed memory limits, single-pass streaming algorithms (\textsc{CluStRE} and \textsc{Hollocou}) partition graphs with $3.3$~billion edges (\texttt{uk-2007-05}) using only a few gigabytes of RAM. Moreover, enabling multi-pass quotient-graph refinement in \textsc{CluStRE} closes nearly the entire modularity gap to \textsc{Leiden} on medium-scale networks.

At the same time, our results show why learning-based methods have gained popularity on attributed networks. In real-world citation and co-purchasing graphs, semantic class labels often disagree with purely structural modularity. By combining node attributes with graph topology, GNNs such as \textsc{MAGI}, \textsc{DGCluster}, \textsc{CommDGI}, and \textsc{UCoDe} match or beat classical heuristics in NMI and Pairwise F1. Crucially, our experiments clarify two mechanisms governing neural clustering performance:
\begin{itemize}
    \item \textbf{Cluster count constraints versus attribute utility:} Under Protocol~A, fixed-$k$ neural models appear much weaker in modularity than classical methods partly because they are restricted to the small number of semantic classes $|C|$, whereas classical methods naturally split graphs into dozens of finer communities. When given the same larger cluster budget ($k = \lceil\sqrt{n}\rceil$ in Protocol~B), untuned GNN modularity rises substantially. Conversely, cluster-free GNNs (\textsc{DGCluster} and \textsc{LIM}) still outperform classical heuristics in NMI without knowing $|C|$, confirming that node attributes genuinely improve semantic recovery.
    \item \textbf{Message-passing resilience to structural versus attribute noise:} Our synthetic ADC-SBM sweeps show that GNN architecture determines failure modes under noise. Concatenating ego-features with neighborhood representations (as in \textsc{MAGI}-SAGE) protects against noisy edges when attributes are clean, but fails when attributes are noisy. Full-graph Laplacian smoothing (\textsc{MAGI}-GCN) or hybrid structural similarity (\textsc{DGCluster}) better handles noisy attributes on clean graph structures.
\end{itemize}

Despite these strengths, current GNN clustering methods face severe practical bottlenecks in scalability and hyperparameter sensitivity. While GPU acceleration under Protocol~S speeds up neural training by $12\times$ to $158\times$ and prevents early epoch truncation on medium graphs, most neural implementations construct dense $\mathcal{O}(n^2)$ matrices in host RAM or exceed the 24~GiB GPU VRAM limit on graphs with more than $10^5$ vertices. In addition, Protocol~B shows that multi-loss neural architectures can suffer from mode collapse under default parameters and require costly hyperparameter tuning on each dataset.

For practitioners choosing a clustering algorithm, these findings suggest three simple guidelines. First, on unattributed networks or large graphs with more than $10^5$ nodes, use \textsc{Leiden} for fast, high-modularity partitions, \textsc{VieClus} when maximum modularity is worth a longer runtime budget, or \textsc{CluStRE} when memory is tightly limited. Second, on small-to-medium attributed networks where semantic communities depend on node features, use \textsc{DGCluster} (when the number of clusters $k$ is unknown) or \textsc{MAGI} (when $k$ is known and a GPU is available). Third, when applying GNN clustering to a new domain without ground-truth labels for validation, avoid multi-term loss functions that require sensitive weight tuning, and prefer single-loss or modularity-guided models such as \textsc{DGCluster} or \textsc{UCoDe}.

Looking ahead, our results point to a clear opportunity for hybrid algorithm design. Current learning-based methods rely on slow gradient descent over soft assignments and dense matrix operations, whereas classical multilevel heuristics use fast, sparse discrete vertex moves but ignore node attributes. Combining sparse multilevel refinement and streaming quotient graphs with lightweight learned attribute similarities could bring the semantic accuracy of GNNs to billion-edge networks without the memory and tuning costs of current deep architectures. By releasing our open-source benchmarking harness, standardized datasets, and containerized solver wrappers, we aim to provide a reproducible foundation for developing and testing this next generation of community detection methods.

\section{Methods}\label{sec:methods}

\subsection{Problem Formulation and Quality Metrics}\label{sec:preliminary}

\paragraph*{\textbf{Graphs and clusterings.}}
An \emph{attributed graph} is defined as $G = (V, E, \mathcal{F})$, where $V = \{v_1, v_2, \dots, v_n\}$ is a set of $n$ vertices, $E \subseteq V \times V$ is a set of $m$ undirected edges, and $\mathcal{F} = \{f_1, f_2, \dots, f_n\}$ is the set of node attribute vectors, with $f_i \in \mathbb{R}^x$ for each vertex $v_i$ and attribute dimension $x$. We write $n := |V|$ and $m := |E|$. For a vertex $u \in V$, its neighborhood is $N(u) := \{v \in V : \{u,v\} \in E\}$ and its degree is $\deg(u) := |N(u)|$. Let $A \in \{0,1\}^{n \times n}$ be the adjacency matrix of $G$, where $A_{ij} = 1$ if $\{v_i,v_j\} \in E$ and $A_{ij} = 0$ otherwise, and let $\mathbf{d} \in \mathbb{R}^n$ be the degree vector with $\mathbf{d}_i = \deg(v_i)$.

A \emph{clustering} $C$ of $G$ is a partition of the vertex set $V$ into $k$ disjoint subsets (clusters) $V_1, \dots, V_k$ such that $V_1 \cup \cdots \cup V_k = V$. Classical algorithms use only the graph structure $(V,E)$, whereas learning-based methods also use the node attributes $\mathcal{F}$ to find communities that are coherent in both link structure and feature similarity.

\paragraph*{\textbf{Modularity.}}
The \emph{modularity} score~\cite{girvan2002,Newman2006} of a clustering is the fraction of edges that fall within clusters minus the expected fraction if edges were wired at random while preserving vertex degrees. Let $L_i := |\{\{u,v\} \in E : u,v \in V_i\}|$ denote the number of edges internal to cluster $V_i$. The modularity of $C$ is defined as
\[Q(C) := \sum_{i = 1}^{k}{\left(\frac{L_i}{m} - \left(\sum_{u \in V_i}{\frac{\deg(u)}{2m}}\right)^2 \right)}. \]
Modularity can also be written in matrix (spectral) form. Let $C \in \{0,1\}^{n \times k}$ be the cluster assignment matrix, where $C_{ip} = 1$ if vertex $v_i$ belongs to cluster $p$ and $C_{ip} = 0$ otherwise. Defining the \emph{modularity matrix} as $B := A - \frac{\mathbf{d}\mathbf{d}^\top}{2m}$, modularity is given by
\[ Q(C) = \frac{1}{2m} \operatorname{Tr}(C^\top B C). \]
This matrix formulation is the starting point for continuous and learning-based methods, which relax the binary matrix $C \in \{0,1\}^{n \times k}$ into a continuous soft-assignment matrix $S \in [0,1]^{n \times k}$ with rows summing to one.

\paragraph*{\textbf{Ground-truth recovery metrics.}}
On networks with known reference communities, we measure agreement between the computed partition and the ground-truth labels using Normalized Mutual Information (NMI)~\cite{danon2005comparing} and an edge-restricted Pairwise F1 score. The Pairwise F1 score is evaluated over connected vertex pairs: an edge $\{u,v\} \in E$ is a true positive ($TP$) if $u$ and $v$ share a cluster in both the computed partition and the ground-truth partition. Defining false positives ($FP$) and false negatives ($FN$) analogously over graph edges, $\text{F1} := \frac{2\mathit{TP}}{2\mathit{TP} + \mathit{FP} + \mathit{FN}}$.

\paragraph*{\textbf{Graph neural networks.}}
Graph neural networks (GNNs) compute vector representations (embeddings) for vertices in an attributed graph by repeatedly aggregating feature information from local graph neighborhoods. In community detection, GNNs map vertices into an embedding space where structurally or semantically similar vertices lie close together. Learning-based clustering algorithms then infer communities by optimizing differentiable relaxations of modularity, mutual information, or contrastive loss functions defined over these embeddings or over soft cluster assignments.

\subsection{Algorithmic Taxonomy and Surveyed Methods}
We organize the surveyed community detection algorithms in Table~\ref{tab:comp} by their optimization paradigm, separating classical combinatorial algorithms from continuous and learning-based methods. Classical methods are grouped by their search mechanism (greedy/multilevel, random-walk, metaheuristic) and execution model (streaming, exact). Learning-based methods are grouped by whether they directly optimize a continuous modularity relaxation or use modularity to guide a contrastive or mutual-information objective. Within each group, methods are presented in chronological order.

\subsubsection{Classical Modularity Optimization Methods}

\paragraph*{\textbf{Greedy agglomeration and multilevel local search.}}
Early modularity maximizers used greedy agglomeration, repeatedly merging pairs of communities to increase modularity. Because purely agglomerative merging often creates unbalanced clusters and scales poorly, later algorithms shifted to multilevel local vertex moves.

\textbf{Clauset--Newman--Moore (\textsc{CNM})}~\cite{cnm2004} is a hierarchical agglomerative algorithm that starts with each vertex in its own singleton cluster and repeatedly merges the pair of communities giving the largest modularity gain. It builds a dendrogram of merges and returns the cut with maximum modularity in $O(md \log n)$ time, where $d$ is the dendrogram depth.

\textbf{Wakita--Tsurumi (\textsc{WT})}~\cite{wt2007} improves on \textsc{CNM} by weighting modularity gains with a community-size consolidation ratio. This encourages more balanced merges and improves runtime scalability on large networks.

\textbf{\textsc{Louvain}}~\cite{louvain2008} replaces community-pair merging with greedy local vertex moves. Each vertex is moved to the neighboring community that gives the largest positive modularity gain. Once no single-vertex move can improve modularity, communities are contracted into supernodes and the process repeats on the coarsened graph. Each pass takes linear time in the number of edges, and only a few passes are needed in practice.

\textbf{\textsc{Leiden}}~\cite{leiden2019} fixes a known flaw of \textsc{Louvain}, which can produce internally disconnected communities. \textsc{Leiden} adds a refinement phase before coarsening that splits and regroups sub-communities through randomized, non-greedy merges, guaranteeing that all communities remain connected and locally optimal.

\paragraph*{\textbf{Random-walk and flow baselines.}}
We include two widely used baselines that define communities through random walks rather than modularity, providing a comparison against flow-based community definitions.

\textbf{\textsc{Walktrap}}~\cite{walktrap2005} uses the idea that short random walks tend to stay inside densely connected communities. It defines a distance between vertices based on their $t$-step random-walk transition probabilities and merges communities bottom-up like \textsc{CNM}, cutting the resulting dendrogram at the partition with highest modularity. Its runtime is $O(m n d)$ for dendrogram depth $d$.

\textbf{\textsc{Infomap}}~\cite{infomap2008} frames community detection as a coding problem, finding a partition that minimizes the expected description length of a random walk under the Map Equation. It combines a \textsc{Louvain}-like multilevel search with submodule and supermodule moves to escape local minima.

\paragraph*{\textbf{Metaheuristics and memetic search.}}
Metaheuristic and ensemble methods invest additional compute time to escape local optima that trap simple greedy search. Examples include Variable Neighborhood Search (\textsc{VNS})~\cite{vns2012}, its decomposition extension \textsc{ADVNDS}~\cite{advnds2019}, and the ensemble method \textsc{CGGCi-RG}~\cite{cggci_rg2012}, which combines recurring community structures across multiple runs.

\textbf{\textsc{COMBO}}~\cite{combo2014} considers pairs of communities and optimizes full vertex redistributions between them using Kernighan--Lin-style moves, rather than moving one vertex at a time. By combining merges, splits, and recombinations in a single move type, \textsc{COMBO} reaches higher modularity than simple greedy search, with an empirical runtime bound of $O(n^2 \log C)$ for $C$ clusters.

\textbf{\textsc{VieClus}}~\cite{vieclus2018} is a parallel memetic (evolutionary) algorithm that maintains a population of partitions and creates new candidate solutions through recombination and mutation. Its recombination operator uses overlay clustering, keeping two vertices in the same cluster only if they share a cluster in both parent partitions, and then refines the offspring with multilevel local search. \textsc{VieClus} runs until a fixed time limit and returns the highest-modularity partition found.

\paragraph*{\textbf{Streaming algorithms.}}
Most classical algorithms require random access to the entire graph in memory, which is difficult on billion-edge networks. Streaming algorithms process vertices or edges sequentially in one or a few passes under a small memory footprint.

\textbf{\textsc{Hollocou}}~\cite{hollocou2017} is a one-pass edge-streaming algorithm. Starting from singleton clusters, it processes edges $(u,v)$ one by one and merges the smaller-volume endpoint community into the larger one whenever both community volumes are below a threshold $v_{\max}$. Under random edge arrival, this rule approximates greedy modularity maximization.

\textbf{\textsc{CluStRE}}~\cite{clustre2025} uses a node-streaming model where each vertex arrives together with its adjacency list. In its one-pass light streaming mode (evaluated in Protocol~A), each arriving node joins the neighbor community that maximizes modularity gain, similar to a single \textsc{Louvain} step. In its multi-pass configurations (evaluated in Protocol~B), \textsc{CluStRE} maintains a compressed quotient graph during streaming and refines it across passes.

\paragraph*{\textbf{Exact solvers.}}
Because modularity maximization is NP-hard~\cite{Brandes2008}, exact solvers use exponential-time search such as integer linear programming (ILP) or weighted partial MaxSAT~\cite{maxsat2025} to certify globally optimal partitions on small networks.

\textbf{\textsc{Bayan}}~\cite{bayan2024} is an exact branch-and-cut algorithm that formulates modularity maximization as an integer program over binary pairwise co-membership variables, subject to triangular transitivity constraints on all node triples. It computes upper bounds from linear programming relaxations and lower bounds using \textsc{COMBO}, branching until the optimality gap is closed.

\subsubsection{Learning-Based Methods}

\paragraph*{\textbf{Continuous and differentiable modularity maximization.}}
These methods replace discrete cluster IDs with continuous soft assignments, optimizing a differentiable modularity loss via gradient descent.

\textbf{\textsc{DMoN}}~\cite{dmon2023} passes node features through a GNN and a softmax layer to produce a soft assignment matrix, which is trained to maximize spectral modularity plus a collapse regularization term that prevents placing all vertices into one cluster.

\textbf{\textsc{GNNS}}~\cite{gnns2022} is a GNN-inspired continuous optimizer that updates soft cluster assignments directly through recurrent matrix multiplications with the modularity matrix, without trainable neural network weights or node attributes. It runs multiple random initializations in parallel batches and discretizes the highest-modularity solution.

\textbf{\textsc{DGCluster}}~\cite{dgcluster2024} removes the need to specify the number of clusters $k$ in advance. A GNN maps vertices onto the positive unit hypersphere so that inner products give pairwise co-membership probabilities for a differentiable modularity loss, optionally combined with an auxiliary similarity loss. Final discrete clusters are extracted from the learned embeddings using \textsc{BIRCH}~\cite{birch1996}.

\textbf{\textsc{LIM}}~\cite{lim2025} also avoids fixing $k$ in advance while using a single modularity loss. It first runs \textsc{Louvain} to find coarse structural community centers, trains a GCN to embed nodes, computes soft assignments from embedding similarity to the centers, and optimizes spectral modularity end-to-end.

\paragraph*{\textbf{Contrastive and mutual-information objectives.}}
Instead of maximizing modularity alone, these methods use modularity to define positive and negative pairs or auxiliary losses in representation learning.

\textbf{\textsc{CommDGI}}~\cite{commdgi2020} extends Deep Graph Infomax by jointly maximizing mutual information between local node embeddings, a global graph summary, and learnable community centers in a soft $k$-means layer, guided by an auxiliary modularity loss.

\textbf{\textsc{UCoDe}}~\cite{ucode2023} applies a contrastive loss directly to the cluster-level modularity matrix $C^\top B C$, pushing diagonal (intra-community) modularity terms up and off-diagonal (inter-community) terms down within a single objective.

\textbf{\textsc{MAGI}}~\cite{magi2024} uses the sign of entries in the modularity matrix $B$ to define positive and negative node pairs for graph contrastive learning. A GNN encoder is trained with a contrastive loss over random-walk mini-batches (GraphSAGE backbone in our default setup, or full-graph GCN as an alternative) before applying $k$-means to the learned embeddings.

\subsection{Benchmarking Interface}\label{sec:evaluation}

As shown in Table~\ref{tab:comp}, more than half of the surveyed algorithms are research prototypes without a standard command-line interface. Even among packaged tools, input graph formats, output formats, and runtime/memory reporting vary widely. To ensure a fair comparison, we wrap all 17 algorithms behind a unified interface:
\[\textsc{Cluster}(G, T_{\max}, p, k, M_{\max}, \mathcal{F})\]
where $G$ is the input graph, $T_{\max}$ is the wall-clock time limit, $p$ is the number of threads, $k$ is the target number of clusters, $M_{\max}$ is the memory limit in gigabytes, and $\mathcal{F}$ are the node features. Parallel solvers use $p$, fixed-$k$ solvers use $k$, and attribute-aware solvers accept $\mathcal{F}$.

When a dataset does not include node attributes (as on the \textsc{DIMACS} suite) but a solver requires features $\mathcal{F}$, we generate a deterministic 69-dimensional feature vector (\texttt{ldp+rni}) for each vertex. This vector concatenates a 5-dimensional standardized Local Degree Profile (vertex degree plus the minimum, maximum, mean, and standard deviation of neighbor degrees) with a 64-dimensional seeded Gaussian Random Node Initialization, providing structural and node-identifying signals without $\mathcal{O}(n^2)$ memory cost. When a solver requires a cluster count $k$, labeled \textsc{Ground-Truth} graphs provide the true class count $|C|$ (or $\max(16, |C|)$ for over-provisioning methods \textsc{DMoN}, \textsc{UCoDe}, and \textsc{GNNS}, following their original evaluation setups), while unlabeled \textsc{DIMACS} graphs use $k = \lceil\sqrt{n}\rceil$.

We use the authors' original source code or standard library implementations (\texttt{igraph}~\cite{igraph2006}, \texttt{cdlib}~\cite{cdlib2019}) with minimal changes, following three timing and reporting rules:
\begin{itemize}
    \item File parsing and writing cluster assignments to disk are excluded from algorithm runtime.
    \item For anytime search algorithms that run until $T_{\max}$ (\textsc{VieClus}), we record the time when the best partition was found.
    \item For neural methods, if training reaches $T_{\max}$ before finishing all epochs, the training loop stops cleanly and outputs the clustering from the current model state.
\end{itemize}

\subsection{Protocols and Parameter Settings}

Our primary evaluation (\textbf{Protocol~A}) tests all algorithms out of the box on a single CPU thread ($p=1$) using author-recommended default parameters, avoiding any dataset-specific tuning. We complement Protocol~A with \textbf{Protocol~S} (hardware scaling), which runs parallel and neural solvers on 32 CPU threads and on an NVIDIA RTX~4090 GPU with default hyperparameters, and \textbf{Protocol~B} (hyperparameter tuning), which runs a 50-trial Optuna~\cite{optuna2019} Bayesian search maximizing modularity $Q$ on Cora, Citeseer, and Pubmed.

\subsection{Computational Environment}

All experiments were run on identical server nodes equipped with a 16-core (32-thread) Intel Xeon w5-3435X CPU, 125~GiB of RAM, and an NVIDIA GeForce RTX~4090 GPU with 24~GiB of VRAM (driver 560.35.03, CUDA~12.6), running Ubuntu~24.04.3~LTS (Linux kernel 6.8.0-107, GCC~13.3.0, Python~3.12.13). Each benchmark job ran exclusively on a node under Linux \texttt{cgroup} memory enforcement with a 1-hour wall-clock limit ($3\,600$~s, plus a $900$~s watchdog grace period for neural epoch termination) and a 120~GB RAM limit (or 24~GiB VRAM on GPU). Runs exceeding the memory limit are recorded as \textsc{MLE}, and runs exceeding the 1-hour limit are recorded as \textsc{TLE}.
